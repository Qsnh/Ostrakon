# Ostrakon 实现计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 用 Go 实现 Ostrakon：零规则配置的类 fail2ban 守护进程，盯 sshd / nginx 日志，交给 Jev 判定是否封禁，用 nftables 执行带超时的封禁；Jev 不可用时暂停、恢复后自动继续。

**Architecture:** 单进程流水线：日志源（文件 tail / journalctl）→ 按源锚定的字段提取器 → 白名单 → 按 IP 滑动窗口触发 → Jev 判定（带重试与暂停状态机）→ nftables set 加超时元素 + 本地状态文件。CLI 子命令通过 unix socket 与守护进程交互。所有外部依赖（Jev HTTP、`nft`、时钟、sleep）都通过接口注入，单元测试不触网、不需要 root；最后在特权 Docker 容器里做 Linux 端到端验证。

**Tech Stack:** Go 1.25，标准库（`net/http`、`net/netip`、`log/slog`、`encoding/json`、`os/exec`），唯一第三方依赖 `golang.org/x/term`（setup 时隐藏输入 key）。Linux 运行时依赖：`nft`、systemd、可选 `journalctl`。

**Spec:** `docs/superpowers/specs/2026-10-18-ostrakon-design.md`（执行者需同时阅读）

## Global Constraints

- 仓库根目录：`ostrakon/`；Go module 路径：`ostrakon`（凌统决定，发布时可改为真实仓库路径）；`go 1.25`。
- 第三方依赖只允许 `golang.org/x/term`。
- 运行平台仅 Linux；但 `go test ./...` 必须在 macOS 上也能通过（Linux 专属逻辑通过注入的 runner/文件内容测试）。交付物：`GOOS=linux CGO_ENABLED=0 go build ./cmd/ostrakon` 产出的单个静态二进制。
- 固定路径：key `/etc/ostrakon/key`（0600）；状态 `/var/lib/ostrakon/state.json`；控制 socket `/run/ostrakon/ostrakon.sock`（0600）；二进制 `/usr/local/bin/ostrakon`；unit `/etc/systemd/system/ostrakon.service`；utmp `/var/run/utmp`。
- Jev：`POST https://api.typesafe.ai/v1/systemone`，`Authorization: Bearer <key>`，`Content-Type: application/json`，`model` 固定 `jev-1.13.0`。
- Key 来源：环境变量 `TYPESAFE_API_KEY`（去首尾空白）优先，其次 `/etc/ostrakon/key`；每次请求重新读取。
- 环境变量 `OSTRAKON_JEV_URL` 可覆盖 Jev base URL（仅用于测试，不写入用户文档）。
- 单元测试禁止访问真实 Jev、禁止执行真实 `nft`/`systemctl`/`journalctl`。
- 不得引入任何面向用户的规则、正则、阈值配置项；所有阈值是代码常量。
- 日志：`log/slog` TextHandler 输出到 stderr（由 journald 收集）。
- CLI 输出使用英文（凌统决定）。
- 每个任务结束时：`gofmt -l .` 无输出、`go vet ./...` 通过、`go test ./...` 通过，然后提交。

## Review Focus

1. **日志文件暂时不存在**（nginx 后装、logrotate 删除后稍后才重建）：tailer 必须继续等待而不是退出 → Task 10 `TestTailMissingThenCreated`、`TestTailRemovedAndRecreatedLater`。
2. **超长 / 含非法 UTF-8 / 控制字符的攻击者字段**（用户名、路径、UA）：不得崩溃，发送给 Jev 的字段 ≤128 个字符且为合法 UTF-8 JSON → Task 4 `TestTruncation`。
3. **状态文件损坏**（断电写一半）：守护进程照常启动，损坏文件被保留改名 → Task 7 `TestCorruptFile`。
4. **IPv4-mapped IPv6（`::ffff:203.0.113.12`）**：必须规范化为 IPv4，白名单匹配与 `banned_v4` set 才能生效 → Task 1 `mapped` 用例、Task 6 `TestBuiltin`、Task 8 `TestBanMapped`。
5. **Jev 返回 200 但答案缺失或选项超出预期**（如 `"forever"`）：不封禁、不进入暂停、记日志 → Task 4 `TestDecideMalformed`。

Syslog 前缀用行首锚定正则：`^(?:[A-Z][a-z]{2} [ \d]\d \d\d:\d\d:\d\d|\d{4}-\d\d-\d\dT\S+) \S+ (?:sshd|sshd-session)\[\d+\]: (.*)$`。消息部分逐个匹配下列**首尾锚定**正则（`(.*)` 为贪婪匹配，从而取到最后一个 `from <ip> port <n>`），IP 捕获组为 `([0-9A-Fa-f:.]+)` 再经 `netip.ParseAddr` 校验并 `Unmap()`：
```
^Failed \S+ for (?:invalid user )?(.*) from IP port \d+(?: ssh2)?$                         -> auth_fail
^maximum authentication attempts exceeded for (?:invalid user )?(.*) from IP port \d+ ssh2 \[preauth\]$ -> auth_fail
^Invalid user (.*) from IP port \d+$                                                       -> invalid_user
^(?:Disconnected from|Connection closed by) invalid user (.*) IP port \d+ \[preauth\]$     -> invalid_user
^(?:Disconnected from|Connection closed by) authenticating user (.*) IP port \d+ \[preauth\]$ -> preauth_close
^Connection closed by IP port \d+ \[preauth\]$                                             -> preauth_close
^Accepted \S+ for (.*) from IP port \d+ ssh2(?:: .*)?$                                     -> auth_success
```

### Task 5: 按 IP 滑动窗口与触发（tracker）

**Files:**
- Create: `ostrakon/internal/tracker/tracker.go`
- Test: `ostrakon/internal/tracker/tracker_test.go`

**Interfaces:**
- Consumes: `event.Event`、各 `event.Kind`
- Produces:
  ```go
  package tracker
  type Config struct { Window, BenignTTL time.Duration; MaxEvents, PerIPCap, MaxIPs int }
  func DefaultConfig() Config // Window 10m, BenignTTL 1h, MaxEvents 50, PerIPCap 400, MaxIPs 100000
  type Batch struct { IP netip.Addr; Events []event.Event } // 时间升序，最多 MaxEvents 个最新事件，含该 IP 所有来源
  type Tracker struct{ /* 内部加锁，可并发调用 */ }
  func New(cfg Config) *Tracker
  func (t *Tracker) Add(ev event.Event) (Batch, bool)
  func (t *Tracker) Done(ip netip.Addr, benign bool) // 清除"判定中"；benign=true 时缓存良性结论
  func (t *Tracker) Forget(ip netip.Addr)            // 封禁后清空该 IP 的一切
  func (t *Tracker) Prune(now time.Time)
  func (t *Tracker) Len() int
  ```
  规则（以 `ev.Time` 为当前时刻，只统计窗口内事件）：
  - `auth_success` 不存储、不触发。
  - 相关事件：sshd 的 `auth_fail`/`invalid_user`/`preauth_close`；nginx-access 的 Status 400–499。
  - 触发：sshd 相关数 ≥ 3；或 nginx 相关数 ≥ 10；或 nginx 总数 ≥ 300。
  - 判定中（Add 返回过 batch 且未 Done/Forget）的 IP 只存事件不触发。
  - 良性缓存：`Done(ip,true)` 记录当时相关总数 N 与到期时间（最后事件时间 + BenignTTL）；缓存期内只有相关总数 ≥ 2N 且满足触发条件才触发；过期后按普通规则。
  - 每 IP 最多保留 PerIPCap 个事件（丢最旧）；IP 数超过 MaxIPs 时淘汰最久未活动的 IP。

  1. `Firewall.Ensure`，失败 → 返回错误（这是致命错误，与 Jev 不可用不同）。
  2. 恢复封禁：对 `Store.ActiveBans(now)` 逐个 `Ban(ip, Until-now)`。
  3. `Allow.SetUser(Store.AllowList())`；立即刷新 Sessions/Local，之后按周期刷新（刷新失败只记 Debug 日志并保留旧值，例如容器里没有 utmp）；每 1m `tracker.Prune`。

  6.
